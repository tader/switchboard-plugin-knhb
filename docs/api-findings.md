# API findings — 2026-10-27

Primary evidence: KNHB’s [Match Center](https://www.knhb.nl/match-center#/), its public [Match Center module](https://mc.static-hw.nl/v2/match-center.js), imported `useApi-CkWXYYfe.js`, `ProgramView-DAWCE3g9.js`, `TeamView-C1v3BJyv.js`, `ClubView-BfKyvc8Y.js`, `MatchDetailView-CrFuAYjr.js` and `ClubsPanel-0UrgOKwy.js`, and [OIDC discovery](https://login.hockeyweerelt.nl/.well-known/openid-configuration).

The current web client uses `https://app.hockeyweerelt.nl`, signed HAPI version **8** requests, and `POST /device/register` with a random UUID and `os: Web`. The signature is SHA-1 of timestamp + sanitized path + concatenated sanitized query pairs in original order + reversed UUID. Query separators are not included in the hash. Request methods and bodies are not signed by this upstream protocol; the plugin therefore enforces read-only proxy access.

For account requests it additionally sends the OIDC **ID token**, not the OAuth access token, in `Authorization: Bearer`. The KNHB website’s public config supplies the website client ID. The Match Center retrieves the signed-in record from `sessionStorage` keys beginning `oidc.user:https://`. This plugin restricts that extraction to KNHB’s exact issuer and website origin and accepts only KNHB’s three published website client audiences. It does not register the website client with an arbitrary Switchboard callback URL.

Observed current routes are `/clubs`, `/clubs/{federation_reference_id}`, `/poules/{pouleId}/teams/{teamId}`, `/matches/{matchId}`, `/my-matches`, `/favorites`, `/favorites/defaults` and `/favorites/defaults/matches`. Team routes use current numeric IDs and poule IDs. The old hockey-timer integration’s `/mc/clubs` and `/mc/teams/N1502/matches/official` both returned 404, so this plugin does not advertise those legacy endpoints.

Live anonymous checks passed device registration, `/clubs`, `/favorites/defaults` and `/favorites/defaults/matches`. The public match feed included `date` with a timezone offset, `home`, `away`, nested `score`, `status`, `role`, `role_name`, `own_team_id` and user-action fields. Initial follow-up probing returned HTTP 429 and stopped. After waiting, live checks also passed `/clubs/HH11JP6`, `/poules/180863/teams/8167` and `/matches/2079193`. The team response contained 132 matches nested under `data.poules[].matches`, covering the entire poule; consumers must filter the requested team ID. `data.neighbors[]` contained related poule IDs and seasons for historical queries. A headless Chrome smoke test also verified the private debugging pipe, empty-session handling and temporary-profile cleanup. Personal sign-in, the account-specific feed and refresh behavior need an interactive account acceptance check. Automated tests use synthetic credentials and mocked server responses; they do not establish upstream account access.

Refresh uses the discovered `/oauth/token` endpoint and captured website client ID. If KNHB requires a different client authentication method, does not provide a refresh token, or omits a usable replacement ID token, the user must reconnect. Rotated refresh tokens are persisted before subsequent ID-token validation. The plugin does not expose a generic bearer-token hook because both per-request device signing and account authentication are needed.
